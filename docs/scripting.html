Animation Scripts

Write your own animations for the LED wall. A script is a short Python file: tell it what color each pixel should be, or draw shapes, text and particles on a canvas. It runs live on the wall, and sliders let you tweak it without touching the code.

What you can make

These all come with the app (Add → Script..., under Examples). Each one is a single file you can open, read and change. They are commented so you can learn from them.

Getting started

Play an example

  1. In the playlist click Add → Script...
  2. Pick a script on the left. The preview shows it running at your display's size.
  3. Change its Settings (sliders, colors, choices); the preview follows right away.
  4. Click OK. The script is now a playlist item. Like a picture it plays for Image s seconds; set Repeat to Loop current to keep it on the wall.

Right-click a script item in the playlist for Edit... (settings) and Edit code....

Make your own

  1. In the Script window click New script... and give it a name. A small starter script is created in My scripts and the editor opens.
  2. Change something and press Ctrl+S (Cmd+S on a Mac). The preview (and the wall, if it's playing) picks up the change at once; no need to restart anything.
  3. If there's a mistake the editor shows the line in red and says what's wrong. The wall keeps the last good picture, dimmed with a red edge, until you fix it.
To change an example, select it and click Edit code. The app makes your own copy in My scripts (with the same name, so playlist items use your version) and leaves the original alone.

Your first script

A script that colors the whole wall red:

def pixel(x, y, t):
    return red

pixel is asked for a color for every pixel, every frame. x goes from 0 (left) to 1 (right), y from 0 (top) to 1 (bottom), and t is the time in seconds. Now use them:

def pixel(x, y, t):
    return hsv(x, 1, 1)          # hue follows x: a rainbow from left to right

hsv(hue, saturation, brightness) makes a color; the hue goes round the rainbow from 0 to 1. Add time to make it move:

def pixel(x, y, t):
    return hsv(x - t * 0.2, 1, 1)  # slides along, one full rainbow every 5 seconds

Give it a slider so you can change the speed without editing:

"""Moving rainbow
My first script.
"""

params = {
    "speed": slider(0.2, 0.05, 2.0),
}

def pixel(x, y, t):
    return hsv(x - t * speed, 1, 1)

The text in """ at the top is the name and description shown in the script list. speed is now a slider on the item, and inside the script it's just a number.

pixel() or frame()?

A script needs at least one of these two functions:

pixel(x, y, t)frame(c, t)
What it doesReturns a color for every pixel, worked out from position and timeDraws on a canvas c: shapes, text, dots, effects
Good forPatterns, gradients, plasma, tunnels, waves, noiseThings that move around: balls, particles, text, sprites; anything with trails
Picture between framesStarts fresh each frameStays until you clear or fade it
ExamplesRainbow wave, Plasma, Lava lamp, TunnelFireworks, Swirl, Bouncing balls, Code rain

You can have both: pixel paints the background first, then frame draws on top. And setup(c), if you write one, runs once when the item starts (see Remembering things).

def frame(c, t):
    c.fade(0.8)                                  # darken what was there: short trails
    x = c.w / 2 + sin(t * 2) * c.w * 0.4             # swing left and right
    c.circle(x, c.h / 2, c.h * 0.2, hsv(t * 0.1))   # a ball that changes color

Position and time

NameMeaning
x, y (in pixel)0..1 across and down the display (0, 0 is the top left)
c.w, c.hWidth and height in pixels. W and H are the same numbers.
aspectW / H, e.g. 2 for a 256 x 128 wall. Multiply x by it to keep circles round in pixel.
tSeconds since the item started (smooth, independent of the frame rate)
c.dtSeconds since the last frame; use it for movement: pos += speed * c.dt
c.frameFrame counter, 0, 1, 2 ...

In frame() drawing works in pixels: c.circle(10, 5, 3) is 10 pixels from the left, 5 down. Positions don't have to be whole numbers; in-between values are drawn smoothly, so slow movement glides instead of jumping a pixel at a time.

Scripts adapt to any wall size. Work in fractions of c.w and c.h (c.h * 0.2) rather than fixed pixel numbers and your script will look right on a 64 x 32 panel and on a 512 x 256 wall.

On LEDs, black is "off" and looks very dark next to lit pixels, while dim colors still glow. Bright, saturated colors on black usually look best; pale pastels can look washed out.

Drawing

All of these are used in frame(c, t) as c.something(...). Shapes are drawn smooth (anti-aliased). Most take two optional extras: alpha= (0..1, see-through) and blend=: "normal" (paint over), "add" (light adds up, like overlapping spotlights) or "max" (keep the brighter of old and new).

c.line(x1, y1, x2, y2, color, width=1)Line
c.rect(x, y, w, h, color)Rectangle, top-left corner at x, y. width=1 for an outline.

Effects

These change the whole picture. Combined with not clearing between frames they make trails, tunnels and kaleidoscopes.

Live data

Scripts can show live information: the weather, stock and crypto prices, YouTube subscribers, news headlines, or a value from any web address. None of the built-in sources needs an account.

Data is fetched in the background, so the animation never stops to wait. A call gives you the latest value it has: None until the first answer arrives (show "Loading..." until then), and after that the newest answer, refreshed on its own. Answers are also saved on disk, so after a restart or a power cut the wall shows the last known values straight away, even before the internet is back.

def frame(c, t):
    c.clear()
    w = weather("Chicago, IL")
    if w is None:
        c.text("Loading...", size=c.h * 0.2)
        return
    c.text(f"{w['temp']:.0f}{w['unit']}", size=c.h * 0.6)    # 53°F
CallGives
weather("Chicago, IL", units="F")Current weather (Open-Meteo). A dict with temp, feels_like, high, low, wind, humidity, description ("Partly cloudy"), icon (clear, partly, cloud, fog, rain, snow, storm), is_day, place, unit ("°F") and hours (the next 12 hours: time, temp, icon). The place can be "Town", "Town, State", "Town, Country" or "41.88, -87.63". units="C" for Celsius. Updates every 10 minutes.
stock("AAPL")A quote (Yahoo Finance): price, change, change_pct, name, currency and history (prices through the day, for a little chart). Stocks (AAPL), indexes (^GSPC = S&P 500, ^DJI = Dow), crypto (BTC-USD, ETH-USD), currencies (EURUSD=X). Every minute.
youtube("@MrBeast")A channel's subscribers (a number), text as YouTube shows it ("30.5M") and name. Takes an @handle or a channel link. YouTube rounds public counts over 1,000 to three digits, so big channels change in steps. Every 5 minutes.
headlines(feed, count=10)A list of headlines from a news feed (RSS or Atom), newest first. Most news sites, blogs and podcasts have one. Every 15 minutes.
fetch(url, every=300)Anything else: the answer from a web address, read as JSON data (kind="text" for plain text). headers={...} sends extra headers, e.g. a login token.
get_path(data, "a.b.0")Digs a value out of JSON data: get_path(d, "bitcoin.usd"), get_path(d, "items.0.name"). None if it isn't there.
data_error("weather")What went wrong last time ("" when fine): "weather", "stock", "youtube", "headlines", "game" or a fetch address.

Your own sources

Lots of services answer with JSON data. Open the address in a browser to see what comes back, then pick the value with a path. The Any number from the web example does exactly this with settings, so you can often just use it. Two ideas:

# a price from CoinGecko (free, no account)
d = fetch("https://api.coingecko.com/api/v3/simple/price?ids=bitcoin&vs_currencies=usd", every=60)
price = get_path(d, "bitcoin.usd")

# a sensor from Home Assistant (make a long-lived token under your profile there)
d = fetch("http://homeassistant.local:8123/api/states/sensor.outside_temperature", every=60,
          headers={"Authorization": "Bearer " + token})
temp = get_path(d, "state")

For a key or token, use a setting that hides what's typed: "token": textbox("", secret=True).

Be kind to free services: the same address is never asked more often than every 15 seconds, and the built-in helpers refresh far less often than that. Prices every minute and weather every 10 minutes are plenty for a wall.

Games and game servers

From the player's game: CS2 live HUD

Counter-Strike 2 can send what's happening in your game to DDP Streamer while you play: health, armor, ammo, money, kills, the score, the bomb and more. This is Valve's own Game State Integration, made for things like this, so it's safe with VAC. The game itself sends the data, so it works on any server: official matchmaking, community servers and your own private server alike.

The CS2 live HUD example uses it. The wall goes white when you're flashed, pulses red when you take damage, bursts on a kill (with HEADSHOT), counts down a planted bomb and sweeps the winning team's color at the end of a round.

Setting it up (CS2 on another computer)

  1. On the computer running DDP Streamer: Add → Script..., pick CS2 live HUD, leave CS2 runs on another computer ticked and click OK. Play the item once. It writes the file gamestate_integration_ddp_streamer.cfg into My scripts (Folder opens it), already set to send to this computer.
  2. If Windows asks whether Python may use the network, allow it on private networks. The game's data can't reach the app otherwise.
  3. Copy that file to the gaming PC, into CS2's game\csgo\cfg folder. The easy way there: in Steam right-click Counter-Strike 2 → Manage → Browse local files, then open game, csgo, cfg.
  4. Start (or restart) CS2 and join a game. The wall switches from "Waiting for the game" to the HUD as soon as data arrives.

If CS2 is on the same computer as DDP Streamer, untick CS2 runs on another computer; the script then puts the file into CS2's folder by itself, and you only restart CS2.

The address in the file is this computer's network address. If it changes (a new router, or the router hands out a different one), play the item again and copy the new file over. Giving this computer a fixed address in your router avoids that.

game_state(3000, any_computer=True) gives the latest data the game sent (a dict), or None before the first. game_info(3000)["age"] says how many seconds ago it last heard from the game; CS2 sends at least every 5 seconds while running. What's in it:

To react to something happening (a kill, damage), remember last frame's value on c and compare, as the CS2 example does.

Server status

Set server address:port to the server's address and game port, e.g. 192.168.1.50:27015 (27015 is the usual port and can be left off). For a server in Docker, use the address of the computer running Docker and the game port it publishes; if players can join it, it's already published.

CS2 servers report how many are playing but leave the names blank, even with host_players_show 2. For CS2 the example takes the names and kills from the server's log instead: set the server up as for the kill feed below. Players show up as soon as they join, kill or die. Bots are dimmer.

In your own scripts: game_server("192.168.1.50:27015") gives name, map, game, players, max_players, bots, ping and list (each player's name, score and time in seconds, best first), or None until it answers.

CS2 kill map

The CS2 kill map example uses the same server log as the kill feed below (same setup). Every kill flashes where it happened, seen from above: a line from the killer to the victim in the killer's team color, and a ring that grows and fades (white for a headshot). The spots of all the fights leave a faint trace, so the map's corridors draw themselves as the match goes on; higher floors are warmer. It starts over on a new map. Add mp_logdetail 3 to the server's config for many more points: every hit, not just kills.

Settings (sliders)

Put a params dictionary at the top of the script. Each entry becomes a control on the item, and inside the script its value is a plain variable with that name.

params = {
    "speed":   slider(1.0, 0.1, 5.0),              # default, lowest, highest
    "count":   slider(50, 10, 500),               # all whole numbers: a whole-number slider
    "tint":    color_picker("#ff2080"),             # becomes an (r, g, b) color
    "colors":  dropdown("fire", "ice", "neon"),     # one of these words
    "trails":  checkbox(True),                    # True or False
    "message": textbox("HELLO"),                   # a line of text
    "key":     textbox("", secret=True),         # typing shows dots (keys, tokens)
}

Every control takes label="..." if the name isn't clear enough (slider(2, 1, 8, label="cell size (px)")). slider(..., step=1) forces whole numbers.

Moving a slider changes the preview immediately. Values that setup() uses (like a number of particles) take effect when the item starts again: click OK, or pick the script again in the list.

Remembering things between frames

Store anything you need later on the canvas c. Set it up once in setup(c), then update it in frame(c, t):

def setup(c):
    c.balls = [[rand(c.w), rand(c.h), rand(-30, 30), rand(-30, 30)] for _ in range(10)]

def frame(c, t):
    c.fade(0.7)
    for b in c.balls:
        b[0] += b[2] * c.dt                      # move by speed x time
        b[1] += b[3] * c.dt
        if not 0 < b[0] < c.w: b[2] = -b[2]       # bounce off the sides
        if not 0 < b[1] < c.h: b[3] = -b[3]
        c.circle(b[0], b[1], 3, hsv(b[0] / c.w))

Moving things by speed * c.dt keeps the speed the same whatever the frame rate.

noise is the secret behind natural-looking movement: fire, water, clouds, aurora. Compare:

rand()               # jumps around: static, sparkle
noise(t)            # drifts smoothly: wind, flicker of a flame, a wandering position
noise(x * 4, y * 4, t)  # soft blobs that slowly change: clouds, plasma

Python's own math, random and numpy (as np) are there too, and you can import other modules.

Whole-picture math

In pixel(x, y, t), x and y aren't single numbers: they are grids holding every pixel's position, and your formula is worked out for the whole wall in one go. That's why it's fast. It also means a plain if on x or y doesn't work; use these instead:

Instead ofWrite
if x < 0.5: a else: bnp.where(x < 0.5, a, b)
a hard edgesmoothstep(0.49, 0.51, x) (a soft one looks better on LEDs anyway)
min(a, b) / max(a, b)np.minimum(a, b) / np.maximum(a, b)

In frame() the same grids are c.x, c.y (0..1) and c.px, c.py (pixels). The canvas itself is c.img: an array of h x w x 3 (red, green, blue, 0..1) you can work on directly with numpy, e.g. c.img[:, :, 0] *= 0.5 halves the red.

Recipes

Trails

def frame(c, t):
    c.fade(0.85)              # 0.5 = short trails, 0.95 = long
    ...draw...

Glowing particles

def setup(c):
    c.px, c.py = rand(0, c.w, n=500), rand(0, c.h, n=500)

def frame(c, t):
    c.fade(0.8)
    c.px += (noise(c.px * 0.05, c.py * 0.05, t) - 0.5) * 60 * c.dt   # drift on a noise "wind"
    c.py += (noise(c.px * 0.05, c.py * 0.05, t + 9) - 0.5) * 60 * c.dt
    c.px %= c.w; c.py %= c.h                                       # wrap round the edges
    c.points(c.px, c.py, cyan)
    c.glow()

Feedback tunnel

def frame(c, t):
    c.zoom(1.06, 3)           # everything grows 6% and turns 3 degrees per frame
    c.fade(0.95)
    c.circle(c.w / 2, c.h / 2, 4, hsv(t * 0.2), width=1)

Text that fits

params = {"message": textbox("HELLO WORLD")}

def frame(c, t):
    c.clear()
    size = c.h * 0.6
    while c.text_width(message, size) > c.w * 0.95:   # shrink until it fits
        size *= 0.9
    c.text(message, color=hsv(t * 0.1), size=size, font="Anton")

Something every few seconds

def setup(c):
    c.next = 0

def frame(c, t):
    if t >= c.next:
        c.next = t + rand(2, 5)                 # again in 2 to 5 seconds
        c.clear(hsv(rand()))                    # a flash of a random color
    c.fade(0.9)

Your logo, bouncing

def frame(c, t):
    c.clear()

Keeping it fast

At 30 frames per second a script has about 33 milliseconds per frame. The examples take 1 to 10 ms on a 256 x 128 wall. If yours stutters, check the "drawing ... fps" figure under Display, and try:

  • Whole-picture math beats loops. A for loop over every pixel in Python is slow; the same formula in pixel() or on c.x/c.y is worked out all at once.
  • Particles: use c.points with arrays rather than c.circle in a loop. Thousands of points are fine; a few hundred circles are fine.
  • Noise is the slow part. Work it out at half size and stretch it up (Fire and Kaleidoscope do this): 
    x, y = c.x[::2, ::2], c.y[::2, ::2]              # every 2nd pixel
n = cv2.resize(fbm(x * 3, y * 3, t), (c.w, c.h))  # back to full size
  • Only depends on x? Work it out once per column and spread it down (Aurora does this): row = c.x[0] is one row of x values; value[None, :] repeats it down the picture.
  • Big walls (512 x 256 and up) have 4 times the pixels of 256 x 128; pixel-heavy scripts slow down accordingly.

When something's wrong

A mistake never stops the playlist. The wall keeps the last good picture, dimmed, with a red edge. The status bar at the bottom of the app says what's wrong, and the editor shows the message and marks the line in red. Fix it, press Ctrl+S (Cmd+S on a Mac), and it carries on.

Message saysUsually means
NameError: name 'spead' is not definedA typo, or a variable used before it's set. Values kept between frames go on c (c.speed).
invalid syntax / expected ':'A missing : after def/if/for, or a missing bracket. The real mistake is often on the line before.
unexpected indent / expected an indented blockIndentation: the lines inside a def, if or for must be indented by 4 spaces.
The truth value of an array ... is ambiguousAn if on x/y in pixel(); use np.where (see Whole-picture math).
the script needs a pixel(x, y, t) or a frame(c, t) functionNeither function is there, or it's spelled differently.
Everything black, no errorColors are 0..1, so (0.002, 0, 0) is nearly off. Or the drawing is outside the display (check you're using pixels in frame and 0..1 in pixel).

Files and sharing

  • Examples live in the app's scripts folder. Updates to the app may replace them, so don't edit them there; Edit code makes your own copy.
  • My scripts are in %APPDATA%\DDP Streamer\scripts on Windows (~/DDP Streamer/scripts elsewhere). Folder in the Script window opens it. Pictures used with c.image can go there too.
  • A script is one .py file: to share one, send the file; to use one, put it in My scripts.
  • Saved live data is in %APPDATA%\DDP Streamer\cache; deleting it is harmless.
  • Settings, including keys typed into secret boxes, are saved in the app's settings file on this computer.
  • You can also edit in VS Code or any editor (Open in other editor); saving there updates the wall the same way.
Scripts are programs. A script can do anything a Python program can, including reading and deleting files. Only use scripts from people you trust, and look through one before you run it.
